Product Red Team · 2026-05-19

Browser Playout Premortem

Frame: six months from now, the no-ffmpeg browser playout path failed in real broadcast operation. These are the product reasons, not just code risks.

Most Likely Failure

Preview video works, but real live-day operation was never drilled end to end with an active current-day schedule and the actual capture runtime.

Most Dangerous Failure

Output silently stalls, drifts, or loses audio while the operator believes the signal is healthy.

Hidden Assumption

OBS/vMix browser capture will behave like the tested Chromium session. That must be proven, not assumed.

Failure Cards

High severity High likelihood

Preview Works, Live Fails

Preview route plays Vimeo, so team assumes live is ready. On air, health still says no live day or active block is wrong. Output shows fallback or wrong content.

Assumption: preview success proves live workflow success.

Warning: degraded output health; no active current-day block.

High severity Medium-high likelihood

Audio Unlock Trap

Reload or capture restart brings video back, but audio remains locked until operator clicks again. Silence is noticed late.

Assumption: one click stays valid for whole broadcast.

Warning: Start Output overlay returns after reload.

High severity Medium likelihood

Runtime Mismatch

System Chromium plays Vimeo HLS, while another browser runtime fails with codec or autoplay behavior. OBS/vMix must be certified separately.

Assumption: all Chromium-like runtimes play same HLS.

Warning: manifest codec errors in headless testing.

Medium-high severity High likelihood

Schedule/Media Drift

Reload seeks by schedule offset, but media duration, range support, or provider timing differs. Output looks plausible but is off.

Assumption: scheduled duration matches playable duration.

Warning: currentTime differs from expected offset.

High severity Medium likelihood

Weak Fallback

Fallback code exists, but approved fallback media is missing or untested. A failure shows emergency slate instead of acceptable brand-safe output.

Assumption: fallback logic equals fallback experience.

Warning: no ready global fallback asset.

High severity Medium likelihood

Recovery Is Underspecified

Operator sees mediaState/debug data but does not know whether to reload, force fallback, return to schedule, or stop broadcast.

Assumption: operators infer recovery steps.

Warning: incident runbook not tied to live media state.

Revised Plan

  • Add Go Live Drill with pass/fail stored in Admin Health.
  • Certify one actual capture runtime first: OBS Browser Source or vMix.
  • Add output drift monitor comparing currentTime to expected offset.
  • Require tested global fallback before a day can go active.
  • Remove or mark legacy all VLC/ffmpeg primary workflow copy.
  • Add incident prompts based on mediaState/audio lock/no active day.
  • Run a 2-hour endurance test with video, slide, image/ad, fallback, reload.

Pre-Launch Checklist

  • Today has active program day and active current block.
  • Actual OBS/vMix runtime plays Vimeo video with audio after Start Output.
  • Reload mid-episode resumes near expected offset.
  • Slide block renders correctly in capture runtime.
  • Bad media triggers approved fallback.
  • Go Live Drill pass is less than 24 hours old.
  • Operator runbook has black screen, silence, stalled video, wrong block steps.
