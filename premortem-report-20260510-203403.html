Premortem report

RTV Planner MVP production readiness failed

Premise: it is 6 months from now. The hardening plan shipped, was declared MVP-ready, and still failed during real broadcast operation.

Most likely failure

Smoke passed, playout failed

Endpoint probes returned HTML and JSON, but the hydrated renderer never reached reliable video playback, fallback, or nonblack pixels in the capture path.

Most dangerous failure

Output token leaked or disabled

Query-string tokens became operationally hard to protect. If unset or leaked, schedule data and playback URLs become exposed.

Hidden assumption

Readiness is not endpoint reachability

Broadcast readiness must prove capture, media playback, fallback, operator recovery, and auditability - not just server response shape.

Red-team findings

P0 Output token in URLs leaks through browser history, logs, capture configs, screenshots, and referrers.

P0 Current smoke does not prove real playout, HLS startup, black-frame detection, audio/autoplay, or fallback.

P1 CSP still allows `unsafe-inline`, `unsafe-eval`, and broad connection/media sources.

P1 Regex HTML sanitization is not a robust XSS boundary for slide HTML.

P1 Audit lacks enforced common write path, actor identity, and previous/next critical values.

P1 No production-like mutation smoke covers upload, sync, publish, CSRF, or audit writes.

Revised plan

1. Browser playout smoke

Add headless browser smoke that waits for renderer state, captures screenshots, asserts nonblack pixels, and tests forced fallback in local/staging.

2. Safer output sessions

Mint short-lived output cookies from admin. Keep query token only for bootstrap, require it in production, and add rotation runbook.

3. Tighten auth and API reads

Keep playout schedule/playback protected by output token. Require admin for catalog search and Reuters listing/sync.

4. Real XSS boundary

Remove arbitrary slide HTML for MVP or replace regex sanitizer with parser-based sanitizer and payload tests.

5. Mandatory audit helper

Force broadcast-critical writes through an audited mutation helper with actor, result, previous/next values, and correlation id.

6. Staging write smoke

Use staging for future sandbox date write tests. Keep live production smoke read-only.
